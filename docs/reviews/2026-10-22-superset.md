## Inspected specimens and design judgment

[The contact sheet](2026-10-22-superset-specimens.jpg) contains all nine
browser-rendered configuration specimens, clearly labelled as such. The full
Aqua Light, Lime Light, Aqua Lime Light and Azure Dark specimens were also
inspected at their original 1500-pixel width. These are fictional workspaces,
not Superset screenshots. TSX, CSS, JSON/TOML and Markdown role examples cover
more than the main syntax colors; they are not a native grammar test.

- **Aura pair:** purple emphasis remains compact against neutral black/paper.
  Light mint buttons keep dark ink. Cards, sidebar, hover and floating surfaces
  form a quiet hierarchy without a family-color wash across the reading area.
- **Aqua pair:** cyan actions and mint badges remain independent. Cold-white
  reading surfaces and neutral hover ink survive the port; Aqua Dark retains
  Aura's reading foundation while changing interactions. Existing white-on-cyan
  light controls remain an accepted soft-contrast choice (1.74:1 in this
  specimen); the badge pair is 1.50:1. These figures are diagnostic, not an
  aesthetic approval score. No additional yellow border or new darker lime was
  spread into reading surfaces.
- **Aqua Lime Light:** UI is deliberately the same as Aqua Light; brighter
  green/cyan/citrus syntax is retained. The fixture reveals the intended softer
  vivid syntax. It was not darkened to force an unrelated contrast target.
- **Lime pair:** the light foundation is green-white, with mint controls and
  restrained citrus detail in the supported search-panel border. Dark reading
  surfaces remain Aura Dark, with the existing mint action and citrus focus.
- **Azure pair:** neutral Fluent surfaces and blue actions remain distinct from
  the summer themes. Floating surfaces, selected list tint and lavender/green
  syntax harmonize with the Fluent blue. The darker blue filled control retains
  its white label; neutral hover icons remain legible on the gray surface.
- **Distribution and states:** reading surfaces occupy most area and remain
  quiet. Hover surfaces are neutral or lightly tinted, not saturated action
  fills. All five chart series are distinct and occupy only a small specimen
  strip; color counts are not used as screen-area proportions. Selection,
  search and illustrative diff overlays were inspected with source text still
  present beneath them. Native Pierre opacity remains a runtime coverage gap.

## Findings and decisions

### Design adjustments delivered

1. Map Superset `accent` to the shared hover surface, not the Aura brand accent.
   Its repeated menu/ghost-button use would otherwise overcolor the interface.
2. Compile editor syntax explicitly instead of relying on Superset's ANSI-based
   fallback. Syntax overrides and terminal palette changes remain independent.
3. Add generic named `base*` aliases for final family/appearance neutrals and
   `ui.chartSeries` in the shared role layer. The port only maps/serializes.
   Palette source values and all existing compiled themes remain unchanged.
4. Use the shared editor accent-bright for the editor cursor, matching VS Code;
   retain the separate terminal action-fill cursor and contrast foreground.
5. Explicitly cover optional warning, success, brand-highlight and terminal
   selection fields so these do not inherit unrelated built-in defaults.

### Accepted choices and native constraints

- Preserve soft Aqua/Lime controls and syntax, Aura's mint identity and Azure's
  Fluent identity. No overall contrast inflation or new palette was applied.
- Superset couples `primary` between filled buttons and link-button text.
  Mint/cyan/green light links are faint against the canvas (1.20:1 Aura Light,
  1.68:1 Aqua Light, 1.46:1 Lime Light); Azure Dark's shared blue link is 2.48:1.
  This is visible in the configuration specimen and requires an independent
  native link token for a complete fix while retaining the accepted fills.
  It is a known native coupling, not claimed as visually approved.
- Sidebar hover and selection use the same native token. Primary hover uses
  90% opacity rather than Aura's independently configured hover hue. JSON
  cannot provide independent unchecked activity/tab/unfocused/remote tokens.
- Destructive button labels can be hard-coded white in the app, and diff-stat
  green/red utilities can bypass theme status colors. Setting all schema fields
  does not override these literal styles. Optional VS Code effects do not run.
- ANSI slots 16–255, application escape-sequence overrides, fonts, window
  geometry, webviews and plugin content remain owned by the application/user.

### Regressions

No change was found in the existing VS Code, Ghostty or Kitty generated
payloads. In the Superset configuration specimens, hovered icons and sidebar
labels remain visible: hover label contrast is at least 8.21:1 and sidebar
selection at least 8.06:1. These checks supplement visual judgment and do not
assert native desktop coverage.

## Remaining runtime coverage and conclusion

`superset browser list` could not reach a desktop: the host-service manifest
reported a dead PID. No actual Superset window, Electron compositor, native
CodeMirror/Shiki/Pierre language grammar, notification, OS light/dark transition,
unfocused window, remote session or macOS font rendering was visually inspected.
The CLI validates parser/storage behavior, not those runtime states. No live
remote connection was created to fabricate coverage.

No VS Code palette, interaction mapping or theme output changed, so there is no
new VS Code interaction to validate in its isolated profile; the full resolved
inventory was refreshed and baseline equality checked instead. Existing VS Code
screenshots are not presented as new runtime evidence.

The delivered port preserves the existing family hierarchy while fully mapping
Superset's public color contract. Configuration specimens support the surface,
emphasis, syntax and terminal relationships. Native desktop visual acceptance
remains open, particularly primary-colored links and actual diff layering;
passing tests and swatches do not close that gap.
