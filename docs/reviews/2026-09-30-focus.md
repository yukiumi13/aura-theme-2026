## Intent and design judgment

The reference's current-level rabbit marker combines cyan, mint and green,
a white boundary and a small glow. A focused control also identifies the
current interaction location. Reuse those source anchors for a transient
boundary, keeping text-input interiors and reading surfaces quiet.

Focus is an independent role, alongside action enhancement and badge emphasis.
The reference anchors are `#50F5E2`, `#64EBAF`, `#75F79E`; the focus ring places
them at 0%, 52%, 100% on a 135-degree gradient. The cyan glow is alpha `66`,
compact mint glow `45`, and inner white edge `ED`. Opacity, stop distribution
and direction are designed adaptations, not additional image samples.

Inputs and primary actions use a 2px ring with a 6px glow; toolbar icons use
a 1.5px ring with a 3px glow. Rings are hollow and ignore pointer events. The
button/icon rings sit inside their controls because native extension actions
can clip overflow. Buttons/icons require `:focus-visible`; input emphasis
requires focus on the actual input, not just a nearby inline toolbar.

**Design adjustment:** replace the old blue focus treatment in the two Aqua
light themes. Optional effects use the bright reference anchors. The native
CSS-off fallback uses existing teal ink `#277D87`; an initial bright-aqua
fallback proved too weak as a single-pixel line. The original native focus
contrast regression checks remain in place and pass.

**Regression prevented:** search markers shared the legacy focus alias.
Separating `searchMatchBorder` preserves list matches, editor/terminal overview
matches and terminal match boundaries while focus changes independently.

**Accepted choices:** white on cyan actions, mint numeric badges, the existing
button hover fill, neutral reading surfaces and existing syntax roles remain.
No animated glow or permanent ring was introduced.

## Complete resolved configuration review

Rebuilt the VS Code port and read/deep-compared every generated theme against
0.9.5: 9 themes, 4,500 UI colors, 432 TextMate rules and 270 semantic entries,
including transparent values and terminal slots. The full generated review
inventory was refreshed. Detailed changed/unchanged keys and hashes are in
`2026-09-30-focus/config-audit.json`.

- Aqua Light and Aqua Lime Light each change ten focus/interaction boundary
  tokens from `#4A80A7` to `#277D87`. Search, diagnostic, selection and diff
  colors remain unchanged. Editor `#F8FCFE`, sidebar `#F5F9FB`, editor ink
  `#4A5861`, syntax and terminal colors remain unchanged.
- The other seven themes are identical to the accepted baseline.
- Action normal/hover roles and numeric badge roles are identical to 0.9.5.
  Focus derives through both Aqua light appearances; other families emit no
  new CSS. Ordinary Aqua Light and its Lime-syntax derivative remain paired.
- Error/warning/info inputs, disabled controls, secondary buttons, editor tabs
  and editor canvases are excluded from gradient focus selectors. The native
  segmented-button separator and autorun/model-picker pseudo-elements are
  preserved by selector exclusions. Native CSS was inspected for clipping and
  pseudo-element collisions. Older Electron masking receives a prefixed form.

These changes keep the large-area color distribution stable and place the
reference colors at the current interaction location. Actual perceived
brightness and geometry still need native visual inspection.
