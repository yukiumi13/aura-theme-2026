# Aqua 0.9.4: compile optional effects from roles

Date: 2026-09-29. Implements the findings in
[the architecture review](2026-09-29-effects-architecture.md). This revision
preserves the accepted default appearance rather than introducing a new palette.

## Ownership and compilation

- `source/aqua.ts` owns marker cyan/green, shared mint/white, and the designed
  shadow inks, with provenance comments distinguishing samples from adaptations.
- `roles/create-aqua-effects.ts` resolves `ui.action.enhancement` normal/hover/
  focus states and `ui.badge.emphasis` fill, edge, glow and label shadow. Opacity
  and stop distribution are explicit role decisions. A badge-only change no
  longer alters the action's mint ends or leaves its focus color out of sync.
- The template adapter carries named structured effect data in its existing
  string dictionary. The port serializes that data into CSS declarations.
- The VS Code renderer owns native selectors and pixel geometry. A template
  produces the installed CSS, and the same build emits an effect inventory.
  The old handwritten `extra/extension/aqua-gradients.css` has been removed.
- Theme registration metadata and presence of roles generate the scope. Aqua
  Light provides the roles; Aqua Lime inherits them; separate Lime opts out.
  The remaining appearances emit no optional CSS rules.
- The runtime loader controller is unchanged. Plain theme JSON still supplies
  the CSS-off fallback. Native foregrounds and focus overrides remain active;
  enhanced fill/edge/shadow colors now belong to their compiled effect roles.

Also centralized the remaining direct dark-decoration colors in the base role
resolver and moved explicit unfocused-modification opacity from the template
adapter into each family's status roles. Numeric legacy compatibility aliases
remain unchanged and are still a documented migration adapter.

## Complete resolved design review

Read and compared all nine generated JSON objects against the actual 0.9.3
VSIX: all 4,500 UI colors, 432 TextMate rules and 270 semantic entries are
unchanged, including transparency, terminal colors and derived variants.
No syntax or reading-surface changes occurred.

Resolved the previous stylesheet's native/custom variables against the baseline
theme, then compared every declaration in normal/hover/focus/button and marker
rules with the new compiled declarations. All eight theme/state combinations
match, including color, opacity, stop positions, edge, shadow and glow. CSS
selector scoping retains the same specificity and light-theme eligibility.
See [artifact hashes and declaration parity](2026-09-29-effect-roles/parity.json).

The review sheet now reads `aqua-effects.json` and the actual delivered CSS,
checks version/hash/scope/declarations, and includes all effect role values,
native mapping rules, normal/hover/focus/combined states, numeric marker samples,
and plain-color fallbacks. It fails for stale/missing output. The HTML browser
render could not be inspected because the browser tool blocks local file URLs;
no workaround was used. The generated data and declarations were inspected
directly, and the affected real VS Code states were checked separately.

**Design conclusion:** cyan-led buttons, mint-to-green small markers, fine white
edges and restrained glow retain the reference's established distribution. The
white-on-color character and cool reading surfaces remain accepted choices.
The structural change gives this design a single source of truth and makes
future changes independently controllable through roles.
