# Kitty active port and interface review

Date: 2026-10-14. Baseline: `7a56460` (`main`, package version `0.9.7`). Work branch: `feat/kitty-modern-port`.

## Intent and delivered structure

The user requested that old themes remain archived and Kitty follow the active Aura compiler, including interface styling where it belongs in the port. The maintained output uses the current nine-theme registry, not the previous hand-converted collection or the inherited single Soft Dark theme. Existing `legacy/ports/kitty` and `legacy/packages/kitty` stay archived; the latter now points to the maintained package. No Mac-installed theme collection was inspected or deleted from cm03.

Shared palettes, semantic roles and terminal surfaces feed a named-variable Kitty template. All nine themes have 33 explicit color fields. The optional port-owned `styles/aura-ui.conf` contains the flat top-tab geometry, whitespace separators, small margins, fine dividers and regular active/inactive tab labels. Body fonts, gamma/composition, padding, transparency, blur and SSH link-opening behavior stay in personal configuration.

## Resolved configuration review

`resolved-kitty.json` records every decoded field and each payload's SHA-256, plus the complete style preset and its hash. `resolved-kitty.html` illustrates tab, reading, URL, cursor, ANSI status and selection relationships for every theme. These are configuration specimens, not Kitty/macOS screenshots, and their CSS geometry does not simulate the cell-based renderer.

Reviewed all nine color configurations, including all 16 ANSI slots, active/inactive tab surfaces, focus/inactive/bell borders, link ink and the macOS titlebar field. Background, foreground, cursor, selections and ANSI values match Ghostty. Active-tab colors match each family's VS Code chrome. Inactive tab labels use the normal muted reading ink rather than disabled/unfocused editor text. Focus borders containing source alpha are composited onto the reading surface.

- Accepted choice: preserve the user's white-on-cyan Aqua/Lime Light active controls. Their 1.74:1 tab contrast is explicitly recorded. The port does not silently darken the accent or change the shared design to satisfy a generic numerical threshold.
- Design adaptation: ordinary inactive tabs use muted reading ink rather than disabled editor ink; typography stays normal instead of Kitty's default bold-italic active label. Light Aqua/Lime inactive labels remain subdued at approximately 3.9:1 and require actual macOS size/weight review.
- Preserved behavior: application-requested body bold/italic and truecolor output are independent of the tab preset. URL color does not make bare filenames into links. Existing private routing scripts remain the mechanism for remote file opening.
- Capability boundary: no claim of Ghostty search-field equivalence, native macOS tabs, rounded VS Code Pill tabs, gradients or hover animation. No custom Python tab renderer is installed.

## Verification and build finding

The focused Kitty/Ghostty checks passed before the full build. The full build exposed an existing loader bug: the helper directory `src/ports/shared` was imported as a port despite having no entrypoint. The loader now requires `index.ts` or `index.js`; a regression check verifies that Kitty loads while shared helpers and non-port files are skipped.

Build validation includes the whole active compiler, not only the new template. A full rebuild also refreshes pre-existing stale names/version metadata in the other older ports and removes tracked historical VSIX files. Those generated side effects were excluded from this change and the historical artifacts retained. Existing VS Code and Ghostty output payloads are byte-for-byte identical to the baseline; no shared palette values were edited.

The official Kitty 0.49.2 Linux release's `kitty.config.load_config` accepted each generated theme together with the style preset with no accumulated bad lines. Its parsed tab style was `separator`, its edge was top, and both tab font styles were normal. This validates the actual parser, not macOS rendering or application interaction.

Final checks passed: 18 Jest suites / 296 tests, TypeScript with no emit, ESLint on all changed code, and `git diff --check`.

The ZIP CRC and every payload were checked against the package: nine themes, one style preset, README, MIT license and Fluent third-party notice. The terminal workflow now builds Kitty, uploads its bundle and attaches it to tag releases. No tag or release was published for this work.

The full VS Code resolved review was regenerated and inspected as a configuration inventory; all shipped VS Code color, token and effect payloads remain identical to the accepted baseline. Existing review sheets were kept instead of committing unrelated reserialization changes.

## Conclusion and remaining runtime coverage

The port delivers a single source of theme colors and a small built-in interface preset that removes bold-italic tab decoration and uses plain top tabs. The resolved states preserve each family's existing identity and leave large terminal reading surfaces unchanged. This is a completed compiler/configuration review, not complete visual approval.

The current host is cm03 and has no Mac GUI or user Kitty configuration. Actual macOS font weight, titlebar behavior, hover/focus rendering, narrow/long tab titles, multiple windows, HiDPI margins, OS appearance switching and the user's Cmd + Click SSH routing remain unverified. Check those using a fictional sample workspace on the Mac before claiming the runtime matches Ghostty.
